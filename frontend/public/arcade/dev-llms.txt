# dev-llms.txt — the arcade's implementation reference

Read `README.md` for what the arcade is and `docs/design.md` for why it is shaped that way. This
file is the other thing: where the code is, what each file owns, the exact shape of every record
it writes, and the defects already known. It assumes you are about to edit something.

Line numbers are approximate — they drift with every edit. Names and constants are exact.

## The five shared deck mechanisms

Four of the five maths drills, the spelling bee and the language engine implement the same deck
algorithm, near-verbatim. The five maths drills no longer each carry a copy: they load
`maths-engine.js` and alias its functions. Read that one file and you have read the four drills.

**`freshFirst(pool, seen, bucket, keyOf)`** — partitions into unseen (`seen[bucket][key] === 0`) and
seen, shuffles each, sorts the seen group by timestamp ascending. Unseen first, then least
recently served. `keyOf` is per drill: `whole|a` for bonds, `a|b` for the three column drills,
`divisor|dividend` for division.

**`markSeen(seen, bucket, key)`** — writes `Date.now()`, evicts the oldest once the bucket hits
`SEEN_CAP` (900). Called from `renderQuestion`, never from the deck builder: the stamp records what
was *served*, not what was *planned*. This matters for testing — the count is already 1 before the
first answer, so it cannot be used to prove a submit was graded.

**`newCycle(pool, seen, bucket, keyOf)`** — re-sorts the pool by oldest-seen, so pass two starts
with the facts that have waited longest.

**The fill loop** — walk the ordered pool, push, count passes. Pass 0 forbids any duplicate;
later passes forbid only an immediate repeat. Without the counter the loop never terminates on a
pool smaller than the deck (Make 10 is 9 splits × 3 blank positions = 27 cards against a deck of
50). Every implementation also carries a `guard` bound (`total * 400`) as a second backstop.

**`noteAttempt(review, key, right, now, ms)`** — `deck.js`. Replaces the old `noteFact`'s
`{n, miss, due}` with a schedule: `{n, miss, ok, lastAt, nextAt, due}` plus, when the caller
measures it, `{ms, spd, base}`. A success climbs `LADDER = [2, 10, 60, 240, 1440]` minutes and sets
`nextAt = now + interval`; a miss resets `ok` to 0 and sets `nextAt = now`. The asymmetry is the
whole schedule — a miss two minutes out would leave the home screen reading "0 due" the moment a
child missed something. `spd` is the ratio to the fact's own baseline (`1.0` = as fast as usual),
dropped entirely below `SPEED_FLOOR = 250 ms`. `due` is kept in sync so a previous build's record
still reads.

**`isDue` / `dueCount` / `reviewFirst`** — `deck.js`. An entry with no `nextAt` (written by an older
build) falls back to the boolean, so a mid-migration record does not lose its queue. `reviewFirst`
returns `{due, rest}`, most-missed first, and the caller filters both to the current level.

**`mastery(bucket, savedAt)`** — `deck.js`. The hub's stars. Takes the strongest value in a bucket
and relaxes it toward 50% by 0.12/day, capped at 7 whole days. Whole days because the curve is
stated per day; a record 300 ms old decaying by a fraction dropped a card a star on the next render.
The arena's own `ema` shape (`{ema: 0.8}`) reads as 80%.

Stars, shared everywhere: `pct >= 90 → 3`, `pct >= 70 → 2`, else 1.

**`record.js`** — the storage contract every page goes through. `load(key, opts)` returns
`{state, data}` with `state` one of `fresh` / `ok` / `migrated` / `corrupt`; `opts.version: 0`
accepts any schema (the hub cannot track seventeen games' versions), `opts.stash: false` reads
without adding to the corrupt stash, `opts.require` names fields a shape check cannot imply.
A corrupt record is stashed under `arcade.corrupt.<key>` (cap 8) and the page shows a banner.

**`backup.js`** — the record as one file. `dump`/`toJSON` read every `arcade.*` key except the
error ring and the corrupt stash; `parse` validates without writing; `restore(parsed, {replace})`
merges by default. Values are stored as the raw strings the games wrote, never re-serialised, so an
older build's record restores byte for byte.

## Per-file reference

### session.js (422)

`KEY = 'arcade.session.v1'`, `KEEP_DAYS = 120`, `MATHS` = the six maths page names.

`SUBJECTS` (44) is the single source of order: twelve entries of `{id, kind, name, note, games}`.
`checkOrder()` throws at load if two `kind: 'lang'` are adjacent or if `SUBJECTS[0]` is not
a language — an IIFE, so it runs before anything else. With seven others and five languages, two
`other`-`other` pairs are expected — savanna run beside maths at the top, the machine shelf beside
piano at the end; the guard does not forbid them because perfect alternation is impossible while
spelling stays first. `BY_GAME` maps page name → subject. `GAME_PAGES` (102) is the manifest the
table is checked against in both directions plus a claim count; `checkManifest()` (120) throws.

`checkPrerequisites()` (109) throws if any subject in the plan has no node in `skills.js`, and if
any graph edge puts a prerequisite after its dependant. The first half is the direction the edge
loop cannot see: it skips edges naming subjects outside the plan, so a graph with eleven nodes and
a plan with twelve threw nothing. Savanna Run shipped into exactly that hole and was caught only
when the probe was written for it. A graph node the plan does not run is still allowed.

| Function | Line | Does |
|---|---|---|
| `dayKey(d)` | 141 | local `YYYY-MM-DD`, not UTC |
| `dayNumber(d)` | 146 | days since epoch, drives maths rotation |
| `read/write` | 156/162 | `write` trims to `KEEP_DAYS` then `setItem` in try/catch |
| `todayRecord` | 172 | the day's record, created on demand |
| `gameFor(subject, d)` | 181 | `games[dayNumber(d) % games.length]` |
| `plan(d)` | 188 | every subject in order with game, href, done — never writes |
| `progress()` | 198 | `{done, total}` for the meter |
| `mark(id, result)` | 218 | returns `{changed, done, total}`; keeps the day's best percentage |
| `streak(d)` | 242 | run of complete days ending today; today counts only once complete |
| `history(n)` | 261 | last n days oldest-first, gaps present with done 0 and `acc: null` |
| `resultPct()` | 303 | reads the score off a finished drill; `%` wins over `N of M` |
| `toast/announce` | 332/379 | inline-styled banner, `id="sessionToast"` |
| `check/start` | 396/404 | observer callback and install |
| `isFinished()` | 321 | reads the marker the page *declares* |

`mark` keeps the day's **best** percentage per subject, not the last: a replay that goes worse must
not lower the day. A result outside 0..100, or not a number, is refused rather than stored — it
would poison the day's mean. `history(n)` reports `acc` as the mean of the subjects that were
actually scored, and `null` for a day of unscored games, because "played but unscored" and "scored
zero" are different days and the strip must be able to tell them apart.

`resultPct()` reads `RESULT_IDS = ['rPct', 'doneText', 'qPct', 'pPct', 'dPct', 'tPct']`. It is
scoped to those ids on purpose: a percentage elsewhere on the page must not be read as the result.
A `%` wins over a fraction when both appear.

`isFinished()` is the load-bearing predicate: if `#done` exists, the marker is `'on'`
when the element has class `stage`, `'show'` when it has class `done`, and `null` otherwise — a
page that declares neither can never be finished. Only if there is no `#done` does it fall back to
`#summaryPanel` + `show`.

`start()` sets `armed = !isFinished()` and installs a `MutationObserver` on `document.body` with
`{subtree: true, attributes: true, attributeFilter: ['class', 'hidden']}`. The filter is not
cosmetic: the games repaint on every keystroke. `fired` prevents a second record per page load.

### piano-engine.js (895)

`window.PianoGame = { init, staffSvg, rhythmSvg, esc }` at 743.

**Pitch constants.** MIDI 60 is middle C and 69 is A4; everything else is derived. `pc(m)` is the
pitch class, `LETTER_AT` maps pitch class → diatonic letter (C♯ shares C's), and `diatonic(m)` =
`octave*7 + letter` is the vertical axis of the staff. `BOTTOM = { treble: 30, bass: 18 }` are the
bottom lines, E4 and G2. `freqOf(m) = 440 * 2^((m-69)/12)`.

**Audio (60–100).** Lazy `AudioContext` in try/catch, resumed when suspended. `playNote(midi, when,
dur)` is a sine plus a triangle an octave up, both decaying. `playChord` offsets by 35 ms so the
attacks separate. `playSeq(notes, bpm)` takes MIDI numbers or `{m, b}` pairs and steps by
`60/bpm * b`, so a piece keeps its minims instead of being flattened to one beat per note. No
samples, no assets.

**Drawing (131–310).** `staffSvg({clef, notes, simul, show, w, h, timeSig, beats, spell, dots,
offset})` draws five lines, the clef glyph, a stem per note (shared and direction-set for
`simul`), an accidental before a black key, and ledger lines at every even step between the staff
and the note.

Three of those options are new and each fixes a gap that made the picture say less than the text:

- `spell: ['♭']` picks the sign. `accidentalOf` defaults to `♯` because MIDI has already lost the
  distinction between C♯4 and D♭4 — they are one key and one staff position — so a caller that
  means a flat has to say so. Sixteen accidental questions carry it, eight sharp and eight flat.
- `timeSig` prints two stacked digits after the clef; `beats` makes each note draw at its written
  duration (`noteHead`: ≥4 hollow stemless, ≥2 hollow stemmed, ≥1 filled, ≥0.5 one flag, less two)
  and draws a barline wherever the running total completes the numerator. `offset` is the beats
  already elapsed before the first note in the window, so a slice taken from the middle of a piece
  puts its barlines in the right places instead of behaving as if it started at bar one.
- `rhythmSvg(items, w, {timeSig, barSig})` draws the note values on a staff with barlines and
  optional signature. `timeSig` is printed and `barSig` is what the barlines are counted from;
  they differ only for "which signature is this bar in", where printing it would print the answer.
  Note the two vocabularies: here `v` is `w h q e` = whole/half/quarter/**eighth**, while
  `noteHead` takes a beat count. They are not derived from each other and `e` means different
  things in each.

`keyboardHtml(mark)` lays out C4–C5 with black keys after the whites whose pitch class has one
above them — `HAS_BLACK_ABOVE = [0,2,5,7,9]` — and every key carries `data-midi`.

| `render` | 340 | paints the figure, picks the answer channel, stamps `seen` |
| `playQuestion` | 400 | chord if `staff.simul`, sequence if several notes, else one |

| `settle` | 435 | scoring, streak, trap on a named distractor, auto-advance |

`state` carries `piece, pieceIndex, pieceRight, pieceMiss, playing` alongside the usual deck

**DOM ids the page must supply:** `home lesson quiz play done confetti hudBest`; home `tiers

### swahili-agree.js (132)

`window.SwahiliAgree` → `{STEMS, stemsFor, asks, cite, question}`. The table behind
`swahili.html`'s `agree` mode, and the only generated content in the arcade whose correctness is
not checkable by doing the sum — hence the citations.

`STEMS` is `stem → {gloss, forms:{class:form}, cites:{class:[entry,field]}}`, four stems
(`dogo`, `zuri`, `pya`, `eupe`), each with ≥3 distinct forms. `cites` names a `SWAHILI_BANK` entry
by its `sw` and the field (`ex_sw` or `trap`) whose text contains the form as a whole word; where
that entry is a noun, its own `class` is the class the form agrees with.

| Function | Line | Does |
|---|---|---|
| `checkStems` | 81 | load-time throw: ≥3 distinct forms, every form cited, every citation cited once |
| `stemsFor` | 102 | the stems that have a form for a class, in table order |
| `asks` | 110 | can this bank entry be asked — noun, has a class, a stem covers it |
| `cite` | 117 | resolves a row against the bank *now*; `null` when the bank no longer shows the form |
| `question` | 131 | `(e, bank, pick) → {stem, cls, answer, gloss, noun, options, cite}` |

`question` takes its randomness as `pick.one(n)` and `pick.shuffle(a)` so a probe drives it without
a page. Options are every form of the **one** stem and nothing else: a distractor from a different
adjective is eliminable by meaning, which is not the skill. `swahili.html` calls it from `prompt`
with the page's own `shuffle`; `cfg.pool` is `SwahiliAgree.asks(e)` for the `agree` mode.

Not in the table, on purpose: `refu` (`mrefu`, `ndefu`) and `eusi` (`cheusi`, `nyeusi`) are both
attested and both two-form, so neither can make a question with more than two options.

`gradeTyped` in full: if `want` is null or `!isQuantity(q.a)`, fall back to case-insensitive
trimmed string equality. Otherwise tolerance `Math.max(Math.abs(want) * 0.02, 0.05)`; then the
unit — `q.unit.split(',')[0].trim()` if present, else `unitOf(q.a)` — compared lowercased with
`²→2` and `³→3` folded, because a phone keyboard has no superscripts. A number that passes with a
failing unit returns `{ok: false, unitOnly: true}`.

Distractors: on a wrong *choice* the engine finds which of `d1/d2/d3` matched by value and prints
`q.trap`. The lookup is by value, so identical text under two keys still resolves; `q.a` never
matches.

Lesson gate (202–205): `if (q.topic && lessonFor(q.topic) && !state.taught[q.topic]) {
paintLesson(q.topic, 'render'); return; }`. `lessonFor` returns null for a topic with no lesson, so
an untaught lesson-less topic quizzes normally rather than blocking. Chips (416–425): `.tick` when
taught, `.new` when a lesson exists and is unread, nothing otherwise.

Storage: `{ best, seen, review, perTier, tier, taught }`. `seen` keyed `t< tier>:<mode>` → question
text → timestamp. `review` keyed by question text.

### The six maths drills

Common shape: `TOTAL = 50`, storage `{best, perLevel|perMode, review, seen}`, `#done.show`,
stars 90/70. The five drills load `maths-engine.js` + `maths-lessons.js`; the arena loads neither.

### maths-engine.js (393)

`window.MathsGame`. Loaded before the drill's inline script, so the aliasing at the top of each
page (`const MG = window.MathsGame; const freshFirst = MG.freshFirst, …`) is safe.

| Export | What it does |
|---|---|
| `freshFirst / markSeen / newCycle / SEEN_CAP` | the shared deck; `keyOf` is the drill's argument |
| `tone / goodSound / badSound / clickSound / audio` | oscillators, lazy context, everything in try/catch |
| `burst(n)` | canvas confetti; mounts `#confetti` lazily, reuses the page's existing one |
| `init(cfg) / open / close / lessonTopic` | the lesson overlay |
| `$ / rnd / shuffle / esc` | the four one-liners every drill had a copy of |

`init(cfg)` takes `{topics, lessons}` and returns `null` if either is missing, so a page without
written content shows no button. `render(topicId)` escapes every authored string but injects
`figs[].svg` as markup — the same split as `science-engine.js`. The dialog injects
`<style id="mathsLessonCSS">` on first build rather than editing five stylesheets; the five drills
have five palettes and a lesson should look like the page it is on.

**Per-drill sounds that stayed local.** `tickSound` (bonds), `whoosh` (addition), `breakSound`
(subtraction), `plopSound` (division) are one-line compositions over `tone`. They are the drill's
own noise, not shared machinery, so they stayed in the page.

### typing-tutor.html (793)

`arcade.typing.v1` = `{ progress: { lessonId: bestAccuracy }, weak: { key: misses } }`. Twelve
lessons in `LESSONS` (322–349), each `{id, name, desc, lines}`; a run is
`lines.slice(0,3).join(' ')` (561). Unlock: `unlocked(i)` (472) reads `curriculum()[i]`, which is
`LESSONS` plus the drill appended last (370); the drill is always unlocked, because it is earned by
the mistakes that built it rather than by the lesson before it.

**The weak-key drill (F-15).** `state.weak` counts every miss against the key that was *wanted*,
cumulatively across runs and saved with the record; `state.keyErr` is this run and drives the
on-screen chips. `buildDrill()` (374) ranks `weak`, scores every word in the twelve lesson texts by
how many of the five worst keys it carries, takes the top fourteen, and appends a four-key run for
any named key the fourteen leave out — the only way `;`, present in one word in the corpus, gets
practised. Space cannot sit inside a word, so a space-only child gets the shortest words instead.
`easeDrill()` (434) halves the counts a clean drill run was built on; a drill records no best score,
since its text is regenerated. Rebuilt at load (455) and at `finish()` (655), and saved at
`finish()` and at `toLessons()` (733) so a lesson abandoned mid-way still counts.

Input path: a visually hidden `#capture` input, refocused by a document-level keydown, drained per
`input` event through `typeChar` (616). Backspace swallowed at `keydown`; Enter → `typeChar('\n')`
where the target has a newline. A miss records against the **expected** key (`state.keyErr[want]`,
`state.weak[want]`), which is what `paintWeak` (603) turns into the five worst-key chips.

Accuracy `round(correct/typed*100)`; WPM `(correct/5)/elapsedMinutes` shown but not used for stars
(95/85/80 on accuracy). `progress[id]` written only on completion and never for the drill (684);
one `save()` per finished run. A timer expiry calls `finish()` without completing, so it writes the
key counts but no score. `#done.show` (694). Audio is WebAudio `tone()` in try/catch — no
`speechSynthesis` here.

### calligraphy.html (769)

`arcade.calligraphy.v1` = `{ best, perTier, review, seen, tier }`, `TOTAL = 20`. Bank strokes are
`{name, pts:[[x,y]…], hint}` in a 0–100 box.

| Function | Line | Does |
|---|---|---|
| `buildQueue` | 341 | `freshFirst` over the tier, sliced to 20 — **no due-first injection** |
| `renderStroke` | 361 | SVG polyline, `w || 4.2`, round caps; guides dashed cinnabar |
| `resample` | 420 | 16 points of equal arc length |
| `scoreStroke` | 438 | pass iff `mean < 9 && endErr < 16` |
| `endDraw` | 446 | judge, score, completion |
| `say` | 638 | `zh-CN`, rate 0.75, voice `/^zh/i` |
| `stopOrder` | 673 | cancel the run, clear `#animInk` |
| `playOrder` | 681 | `ArcadeStrokeAnim.timeline` → one `requestAnimationFrame` loop; reduced motion steps instead |

Shape and direction are scored in `stroke-grade.js`, not in the page: `strokeScore` is the
16-point resample plus a chord cosine, and `diagnose` returns `right` / `later` / `earlier` /
`shape` against the whole character. The page branches on the verdict, never on `score.ok` -- for
a stroke drawn out of order `score` is the pass against the stroke it *does* match.

The endpoint term is the direction check: a reversed stroke covers the same pixels and fails on
the last resampled point. Each accepted stroke `score += 6`; a wrong stroke resets the streak and
records `char + ' stroke ' + n` in `review`.

### savanna-run.html (837) + algebra-bank.js (170) + african-history.js (150)

## Conventions

- **`esc()`** — defined in both engines and in the pages that interpolate bank text
  (`addition-quest`, `calligraphy`, `chinese`, `french`, `spelling-bee`, `swahili`, `piano-engine`). Maths and
  typing pages carry none because they interpolate only authored numbers; add one before
  interpolating anything a learner typed or any bank string.
- **`show(id)`** — stage switching is `s.classList.toggle('on', s.id === id)` in every page that
  has stages; `.stage { display:none }` / `.stage.on { display:block }`.
- **Inline styles in `session.js`** — deliberate: the games share no stylesheet and several do
  not define the accent variables.
- **Every `localStorage` call is in `try/catch`.** A full quota costs a save, not the game.
- **`SEEN_CAP` per family**: 900 maths drills, 1,400 spelling, 1,200 language, science and piano
  engines, 600 arena.
- **CSS grid `1fr` is `minmax(auto,1fr)`.** Any grid child containing a wide table needs
  `minmax(0,1fr)` or the child's min-content width wins and the inner `overflow:auto` never
  scrolls. This is exactly what broke `times-table-academy`'s explore grid.

## Fixed defects

These were found by reading the sources and are now repaired. Each is listed so a future reader
knows the shape of the bug rather than rediscovering it, and so a regression is recognisable.

1. `science-engine.js` declared `SEEN_CAP = 1200` and never applied it. It now calls a local
   `markSeen()` (same eviction as the language engine) instead of writing `bucket[key] = Date.now()`
   directly.
2. `science-engine.js` never reset `#qHintBox` between questions, so a clue stayed open. `render()`
   now hides and clears it with the rest of the per-question state.
3. `#lHome` on the lesson stage had no listener. It now leaves the lesson *without* marking the
   topic taught, and returns to the quiz when the lesson was opened with "Teach me this"
   (`lessonResume === 'keep'`), to the home screen when it opened automatically.
4. `calligraphy.html` set `state.traceMode` and never read it, so trace and order were identical.
   The ghost is now populated from the character (`#charGhost.textContent = e.char`), shown from
   the first stroke in trace mode and only on completion in order mode.
5. `spelling-bee.html` `startStudy()` reset `index` and `mode` but not `right`/`misses`/`hints`,
   so a study deck running to its end persisted the previous mode's percentage. It now resets them.
6. `spelling-bee.html` defined `differPool()` and `hasConfusable()` and called neither. Both are
   removed; the differ drill fills its options with `nearMiss()` as designed.
7. `infinite-arena.html` initialised `state.length = 10` while the markup marked the **50** button
   `aria-pressed="true"`. The default is now 50.
8. `swahili.html` and `chinese.html` each branched on `mode === 'en2fr'` and called an `en2fr`
   defined in neither file. The dead branch is removed from both `prompt` callbacks.
9. `favicon.svg` was referenced by no page. It has been redrawn in the arcade's own palette (ink
   field, cream border, four pips) and every page now declares
   `<link rel="icon" href="./favicon.svg" type="image/svg+xml">` after the charset meta.
10. `index.html` defined `--soft`, a blur shadow, in a system with none, and nothing used it. It is
    removed.

11. `piano.html` hid `#qChoices` with the `hidden` attribute in keyboard mode, but
    `.choices{display:grid}` is an author rule and beats the user agent's `[hidden]{display:none}`,
    so the choice buttons stayed on screen beside the keyboard. The page now states the precedence:
    `[hidden]{display:none!important}`.
12. `piano-engine.js` built the black keys by testing the *white* key's pitch class, so a black key
    appeared after every white key except C, E, B and the octave C — seven keys where five belong,
    and the wrong five. The gap is now computed from `HAS_BLACK_ABOVE` on the white key and the
    black key is `m + 1`.
13. `piano-bank.js` gave the eight accidental questions a duplicate option (the natural, listed
    twice), and the renderer de-duplicates, so they silently became three-option questions. The
    three options are now the natural, the white key above and the black key above that.
14. `piano-bank.js` gave the octave interval a `null` third distractor, because the neighbour
    offsets ran past the end of the table and only two survived. The offsets now walk backwards
    from the end.
15. The piano page taught rhythm as text and drew note values as bare glyphs: no staff, no time
    signature, no barline. A learner could recite "4/4 means four crotchets" and never decode a
    bar. `rhythmSvg` now draws a bar on a staff with a signature and barlines, and the bank asks
    five questions about a complete bar.
16. Every accidental on the page was a sharp. `staffSvg` emitted `♯` unconditionally, so the
    eight flat spellings of the same five black keys did not exist as questions and a flat sign
    was never drawn. `spell` picks the sign and the flat questions answer with the flat letter.
17. The play stage discarded each piece note's beat count: `p.notes.map(n => n.m)` dropped `.b`,
    so Hot Cross Buns's minims and semibreves were drawn and played as even crotchets. The staff
    is rhythmically wrong without it, and the defect is invisible because the notes are right.
18. The semibreve rest and the minim rest were the same 18×7 rectangle at the same `y`. The
    figure for "how many beats of silence is a minim rest" was the semibreve rest's figure.
19. The five maths drills each carried their own copy of `freshFirst`/`markSeen`/`newCycle` and
    the audio, and the copies had drifted: `freshFirst` took four different signatures, `SEEN_CAP`
    was applied in three and only declared in two, and the streak flourish existed in three of
    five. They now load `maths-engine.js`. The interaction stayed inline — the engine owns the
    deck, not the drill.
20. A maths drill had a worked example and no page saying what the idea was. `maths-lessons.js`
    adds twenty lessons (four per drill), opened from a **Learn** button rather than scheduled:
    a drill has modes and a generated pool, so unlike the science engine there is no first
    question on a topic to hang an automatic lesson on.
21. Moving the freshness deck into `maths-engine.js` silently broke division's key. The old local
    `freshFirst` hardcoded `divisor|dividend`; the shared one defaults to `a|b`, and a division
    fact has no `a` or `b`, so every fact keyed as `undefined|undefined` while `markSeen` still
    wrote `divisor|dividend`. Nothing failed: the drill played, graded and scored, and only
    forgot what it had served. Both division and number bonds now pass their own `keyOf`.
    `probes/freshness.py` exists because no play-through probe can see this class of bug.

Two properties survive all thirty-two: no page makes a request outside its own origin (the favicon
is a sibling file), and all 19 pages still initialise from `file://`.

## Adding a game

1. Copy the nearest page of the same shape. Do not invent a structure — the shared deck
   mechanisms are what make a new drill cheap.
2. Declare a completion marker: `<div class="stage" id="done">` toggled to `.on`, or
   `<div class="done" id="done">` toggled to `.show`, or `#summaryPanel.show`. Load `session.js`.
   Nothing else wires the subject.
3. Storage key `arcade.<game>.v1` with `{best, perLevel|perMode, review, seen}`; wrap every write
   in `try/catch`; cap `seen` at 900 (or the family's value) and trim on write.
4. A card in `index.html` with `data-key` and `data-bucket` matching the bucket name.
5. A subject entry in `session.js` with the right `kind`, slotted so no two `lang` are adjacent and
   the plan still opens on a language — the load-time guard throws if either breaks.
6. A row in the README storage table, a section in `docs/design.md` saying what it teaches and why
   the interaction is shaped that way, and an entry in `llms.txt`.
7. Probe it: no page errors, no external requests, no overflow at 390 px, and the tracker records
   the subject once and not on reload. Canary each probe.

Two traps found while building `piano.html`, both cheap to avoid and invisible when you hit them.
**A `hidden` attribute loses to any author `display` rule on the same element** — a grid or flex
container needs `[hidden]{display:none!important}` or the element stays visible. **An option
duplicated in the bank is deleted by the renderer's de-duplication**, so the question silently
loses a choice; assert `new Set([a,d1,d2,d3]).size === 4` over the whole bank, not just the first
few entries.
